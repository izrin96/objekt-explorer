A post is a list

One card per list, or per linked have + want pair. A 200-entry have list is one post, not 200 rows. Member and season filters keep posts that contain a match.

Lean“They want something I own” is on by default for signed-in users. It turns the board into a to-do list.

Freshness

lists has no updatedAt. Add one that changes when entries change, plus a Bump limited to once every 24h. A post idle for 30 days drops off until bumped.

Consent

A new per-list Show on Trade toggle, off for existing lists. discoverable keeps its current meaning: findable by matching.

Stale entries

A have entry whose token has left the owner's wallet is hidden from the post.

WTB prices

Want lists need a currency to carry a top price. Only sale lists have one today.

How verification works

  • The indexer already publishes transfers on Valkey.
  • A worker subscriber (not the web instances, which would each run it again) matches transfers against open legs by objekt_id, or by collection for “any copy”.
  • A matched leg stores the tx hash. The last leg completes the trade.
LeanSuggest that the newer trader sends first, shown to both sides, but don't enforce it.

Out of scope

Escrow, or holding any money or objekts. The site only records the agreement and verifies the result.

09

Under the hood

Postgres is the source of truth. The socket only nudges. A reconnecting tab asks oRPC for anything newer than its last id.

exists todaynew

Security

The new socket uses the session cookie, so it must check Origin against SITE_URL. Without that, any site could open it as the user (cross-site WebSocket hijacking). The public /ws can stay open as it is.

Why not send over WS

Sending through oRPC keeps validation, auth and rate limits in one place, matches the read-only /ws pattern you already have, and works when the socket is down.

Multi-instance

Each web instance subscribes to user:{id} only for the sockets it holds. With exactly one instance, this step can wait.
