What changes

  • One post per row, full width. No more two-up grid, so no row is stretched by its neighbour.
  • HAVE ⇄ WANT side by side for a trade pair; WTS shows one SALE strip with prices; WTB one WANT strip.
  • Thumbnails go from 40 to 56 px and never wrap. A strip shows what fits its width and ends in +N. Resize the window to see it.
  • List name, description and match counts become one muted line under the strips.
  • The byline column carries trust, active hours (section 04) and when it was bumped.

Code

browse-post.tsx, post-side.tsx (fit instead of STRIP_LIMIT), and browse-view.tsx loses the POSTS_PER_ROW chunking: one post per virtual item.

Your callKeep each post as a bordered card (shown), or drop the border and split rows with a rule for a denser feed?

How it works

  • Stored as an IANA zone plus ranges in minutes, so daylight saving is handled.
  • Off by default. A timezone narrows where someone lives, so viewers only ever see converted times.
  • Browse gets an Active now toggle next to Only matches.

Alternative

Centrifugo already has a personal channel per user, so presence could show “Online now” with no setting. It only covers this minute and says nothing to someone browsing at 3 am, so it's an addition, not a replacement.

Your callShip declared hours alone first, or together with live “Online now”?

Decisions for you

Each one changes what gets built. The proposed answer is in bold.

D1

Browse row style

Bordered card per post, or borderless rows split by a rule for more density.

D2

Match chip under a filter

Counts the whole post, or only what the filter shows.

D3

One-sided filter results

A post whose WANT side has nothing matching still shows, with “0 matching · 8 others”, or the empty side hides.

D4

Active hours scope

Declared hours first, live “Online now” later; or both at once.

D5

Organise the display

Skip until the one-line layout ships; a comfortable/compact toggle is the cheapest version if it comes back.

D6

Unscanned objekts

Skip on Trade: they have no token, so nothing can be verified. Handle as “physical objekt” inside group orders.

D7

Order of work

01 + 03 (web only) → 02 (web + feed query) → 04 (migration) → group orders as their own OpenSpec changes.
