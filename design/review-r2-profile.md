## How signed-in surfaces were checked

`VITE_SITE_URL` points at `:3200`, so the Better Auth cookie resolves only on `web`. Every signed-in
website surface (user menu, account dialog, edit-profile sheet, pin actions, `/link`) was therefore read
from **website source only** and compared with the running signed-in `web`. No mutation was submitted:
no unlink, no delete, no profile edit, no sign-out, no `db:*`. Two read-only `SELECT`s were run against
the production databases to size two findings (`PR-1`, `PR-3`, `PR-10`); nothing was written.

The website's `/@nickname` **collection** tab does not finish its SSR stream in this dev environment
(the route hangs on an unresolved `<template id="B:0">` boundary); client-side navigation into the tab
works, so every website collection comparison below was made after navigating client-side from another
tab. Named in **Could not verify** as well.

## Deliberate differences confirmed

- **`packages/api` is shared.** Both apps import `@repo/api/schemas/user`, `@repo/api/services/auth` and the same ORPC routers, so every privacy rule (`hideUser`, `hideNickname`, `privateSerial`, `hideTransfer`, `privateProfile`) resolves identically. Plan §1, change C0.
- **Base UI in place of intentui / react-aria-components.** No import from `apps/website`, `apps/lab`, `intentui` or `react-aria-components` anywhere in the profile, auth, account, link or live features. Plan §1 rules.
- **`validateSearch` + zod in place of `nuqs`.** `features/filters/search-schema.ts` is the single source for URL state. Plan §1. PR-3 is the one place where that rule was applied by dropping a parameter instead of adding it to the schema.
- **A dedicated Pinned shelf** above the grid instead of hoisting pins into it — lab design, round 1 already recorded it as intentional (`pinned-shelf.tsx`).
- **A summary count strip** (owned / collections / pinned / locked) above the tabs — an addition with no website counterpart (`routes/@{$nickname}/route.tsx:42-61`).
- **Banner hide/show** — an addition (`profile-header.tsx:85-101`), with the collapsed state kept as a short blurred hint strip (`profile-banner.tsx:45,77-84`).
- **Checkpoint granularity is a day, not an instant.** `openspec/specs/web-profile/spec.md:37-39` specifies "a date … the end of that day". PR-13 is therefore narrowed to the label and the re-Apply rounding, not the picker.
- **The summary count strip and the five-tab set** are both specified (`spec.md:10-12`), so they are intended additions rather than drift.
- **Metadata moved into the drawer's Metadata tab** — round 1 P3, out of my scope, unchanged.
