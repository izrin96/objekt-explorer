# web

TanStack Start app on Base UI (the cnippet registry). `src/components/ui/*` are vendored registry copies kept verbatim; `src/components/ui/README.md` lists the only local edits, and the upstream variants to check before composing a new UI pattern or a `components/shared` wrapper.

## Rules

- **State.** URL state is the route's `validateSearch` with Zod. Zustand reads are selectors (`useFilters((s) => s.member)`), never the whole store.
- **Data.** Server data goes through React Query with the `@orpc/tanstack-query` utils: a feature's options live in its `queries.ts` and take their key from oRPC (`orpc.X.queryOptions`, `infiniteOptions`, or `orpc.X.key()` beside a fetch of their own); a key of your own is for a server function or a plain GET. Route loaders load the first paint with `queryClient.query({ ...options, staleTime: "static" })`. `useSuspenseQueries` has no `enabled: false` (it suspends forever), so fetch unconditionally and ignore the result when it does not apply.
- **Round trips.** A loader starts the reads that don't need each other in one `Promise.all`: in the browser the oRPC client batches calls issued together into one HTTP request, and on the server they are in-process calls that run side by side. When a read waits on another only to build its input, give it an endpoint keyed by what the loader already holds (`list.profilePreviews` takes the profile's address, so `routes/@{$nickname}/list.tsx` asks for the lists and their previews together). A read that asks the indexer stays a request of its own, off the read the server renders from: a want list's rules take many times longer than its header, so `startListReads` starts them in the browser. The rules for the queries behind a request are Round trips in `packages/api/AGENTS.md`.
- **Strings.** Every user-facing string is `m.*` from Paraglide. A dialog's dismiss button is `m.common_modal_cancel()` when the dialog has a primary action that commits something, and `m.common_modal_close()` when it is informational or only produces output to copy.
- **API errors.** Show an oRPC error through `refusalText(error)` (`lib/refusal.ts`) or the domain's own formatter (`features/chat/format.ts`), never `error.message`; Better Auth calls in `features/auth/` and `features/account/` keep Better Auth's message.
- **UI kit.** Phosphor icons; `virtua` for grids. An objekt grid in a dialog or sheet takes its columns from `useCardColumns` (`features/objekt/use-card-columns.ts`): `VirtualCardGrid` (a `PanelCardGrid` in a `FadeScrollArea` of its own, `components/shared/fade-scroll-area.tsx`) in a fixed-height body under a filter bar that stays put, `PanelCardGrid` inside a `SheetPanel` or `DialogPanel` (virtua's `Virtualizer` inside the panel's own scroll area, so the panel keeps its edge fades and scrollbar; Trade's "+N" sheet, `side-items-sheet.tsx`), and `CardGridSkeleton` while any loads. `PanelCardGrid` wraps its rows in Base UI's `ScrollArea.Content`: the scroll area otherwise only watches its viewport's box, and the fades miss the grid growing until the first scroll. Any other scroller of its own in a sheet, dialog or popover (a `max-h` list, a flex column) is a `FadeScrollArea`, not the vendored `ScrollArea`, whose `h-full` viewport only a set height bounds and whose focus ring the fade mask clips. The virtual grids start the next page a viewport before the end, since the sentinel's margin is measured against the window, so their `more.load` is `fetchNextPage({ cancelRefetch: false })`: the scroll handler and the sentinel can both call it before `loading` renders.
- **Components.** Before using a cnippet component, read its page as markdown: `https://ui.cnippet.dev/llms.txt` lists every page, and `.md` on a page URL gives its docs. Compose with the part names from its Anatomy section (`DialogPopup`, `MenuPopup`, `SelectPopup`) and swap the rendered element through the `render` prop (`<DialogTrigger render={<Button variant="outline" />}>`); `asChild` is Radix's API and has no effect here. Add a component as `@cnippet/<name>` (see `components/ui/README.md`): a bare name installs the shadcn (Radix) version.
- **Tokens.** cnippet token names only. `text-*-foreground` on a feedback colour is text on a tinted chip, not on a solid fill: text on a solid fill is `text-white`, and a tint is an opacity modifier on the fill (`bg-destructive/8`), since there is no `*-subtle` token.
- **Lists.** Where a list lives and who owns it key off its profile **address**; `isProfileBind` only decides whether it shows on that profile (`features/list/list-link.ts`).
- **Overflow guard.** `lib/dev-overflow-guard.ts` reports horizontal overflow in dev. Declare every deliberate horizontal scroller with `data-scroll-x`, or the guard reports it.
- **Spin rows.** `/activity` and Activity history draw their rows through `foldSpinRows` (`features/activity/spin-rows.ts`, tested), which folds a reward into its spin row in the All view, and the spin cell is `SpinOutcome`. Both skip the grouping under `spins=raw` (the Group spins toggle, `spin-grouping.tsx`), a view that each surface's reset keeps. A query mapper that rebuilds items keeps `spin` and `rewardOf`. On the live feed, `pairLiveRewards` (`live-spins.ts`) runs on the whole socket batch before `matchesFilters`, since a Spin feed never lists the mint that rewards its rows; a pending spin turns broke against `LiveFeed.clock`, the newest transfer time the socket sent before filtering, so a narrow filter still sees time pass.
- **Feature order.** `features/` imports run one way: list < offers < chat < trade, so a feature imports only the ones below it; a symbol two features share goes down to `lib/`, `components/shared/` or the lower feature. The exceptions: list's page shell (`list-view`, `list-header`, `edit-list-dialog`, `create-list-dialog`) imports trade and chat for Post it and `MessageButton`, and offers imports chat's `queries.ts` and `format.ts`, since an offer is a chat message.
- **Where code goes.** Logic with no JSX is a `.ts` module beside its test, and the component imports it (`features/trade/show-matches.ts`, `features/list/rules/rule-layout.ts`). A `.tsx` that exports a component exports only components, string or number constants, types, and objects of components: a hook, context, helper or other object it shares lives in a module beside it (`use-cosmo-artist.ts` beside `cosmo-artist-provider.tsx`, holding the context and its hooks). Vite's Fast Refresh hot-swaps a component module only when every export passes, so one stray export makes each edit to that file reload the page ("Could not Fast Refresh"). A `.tsx` with JSX and no component (`rich-message.tsx`, `use-owner-actions.tsx`) may export anything, since its edits pass up to its importers. Route files are exempt: TanStack's plugin handles their `Route` export. A route file holds the route's config; a loader or `head` that several routes share lives in their feature (`features/profile/tab-route.ts`). The React Compiler memoizes components and hooks, so write plain functions and values.
- **Reuse first.** Before writing a component, hook or helper, search for one that does the job in `components/shared/`, `hooks/`, `lib/`, `@repo/lib` and the feature that owns the domain, and reuse or extend it. A new shared export opens with a one-line doc comment saying what it does: that comment is what the next search finds.
- **Section chrome.** A route under `trade/` that brings its own heading sets `staticData: { tradeChrome: false }` (declared in `router.tsx`), and `trade/route.tsx` then drops the Trade header and tabs; the trade page uses it for its breadcrumb.

## Look

Quiet chrome, loud cards. The page is neutral zinc in both themes, with a near-black or white primary, and the objekt cards carry the colour. Colour elsewhere means something and comes from `lib/tone.ts`: list types (have teal, want amber, sale rose), progress indigo, and success, warning and destructive, each a chip of ink on a tint with an edge in Badge's recipe. Indigo `accent` is for focus and the current selection, not decoration. `font-mono` (JetBrains Mono, slashed zero) marks an identifier, a value read character by character to copy or compare: serials, collection numbers, addresses, deal numbers. Every other number (counts, prices, percentages, ranks, dates) is the sans with its proportional figures. `tabular-nums` is for digits that line up or change in place: a table column, stacked rows of times or stats, a timer, a character counter, a live count such as the unread badge. A number alone in a badge, chip, tab, button, heading, sentence or " · " line reads better proportional, and `font-mono` is already even-width. Labels, badges and names are the sans; prose is the sans (Google Sans Flex) and titles are `font-display` (Instrument Sans). Metadata reads as a " · " line. A new screen reuses these tokens and the vendored components before it adds anything; a design skill's palette, font or motion library gives way to this.

## Presence

A person's online dot is `OnlineAvatar` (`features/presence/online-avatar.tsx`), a green dot while online and an amber crescent (`TONE_SOLID.warning`) while idle, and text that says "Online" or "Idle" reads `usePresenceStatus(userId)` (`"online" | "idle" | null`, `null` before hydration); `PersonAvatar` stays free of presence, since the hover card, Market and signed-out pages use it. Pass no `userId` for the viewer's own avatar. `usePresenceStatus` watches the id while it is mounted, so the watched set is what is mounted (all of a plain list, only the rows on screen of a virtua one), an id no avatar shows any more forgets its answer, and the tab's one `usePresencePoller`, mounted beside `useUserSocket` for signed-in users only, asks `presence.online` for it (`stores/presence.ts`, pure parts in `watch.ts`, where `applyPresence` keeps `idle` a subset of `online`), reading `idle ?? []` for a server from before it. A failed or refused check changes nothing. Beside the poller, `useActivityReporter` tells the server the viewer is active: on a pointer press or move, a key or the wheel in a visible tab, on coming back to the tab and once on mount, it sends `presence.active` when `shouldReport` (`activity.ts`) allows, at most once a minute across all the viewer's tabs: the last report sits in `localStorage` under `lastReportKey(userId)`, since the mark is per person and switching through many tabs would otherwise run into the server's limit. A tab reads storage only once its own clock allows, and a failed report writes its retry time only over its own report. It does not listen for `scroll`, which also fires for scrolls the app makes. A failure shows nothing and lets activity retry after 10 s (`failedReportAt`).

## Staff area

`/mod` is one layout (`routes/(container)/mod/route.tsx`): its `beforeLoad` shows not-found to anyone who is not staff before any loader runs, returns `{ viewerRole }`, and draws the tab strip above each page. The tabs live in `features/moderation/staff-tabs.ts` (tested): add a tab there, and give its route a `beforeLoad` that throws `notFound()` unless `canOpenTab`. `/mod` itself redirects to the viewer's first tab. The Collections tab reads the collection list client-side, since `collectionOptions` is a relative GET the server cannot make. Trade tracking and Message totals (`features/moderation/tracking/`) keep their range in the URL through `staffRangeSearchSchema`, which coerces first: the router's `parseSearch` leaves every value a string, so a bare `staffDaysSchema` reads `?days=7` as 30. Each per-day chart (`DayBars`) carries a visually hidden table of its days, since `ChartContainer` draws nothing until it is measured, on the server included.

## Banner upload

The Edit profile dialog never uploads a banner as picked unless it must. `bannerPlan` (`features/link/banner-rules.ts`, tested) decides at pick time: stills up to 25 MB, GIF and video up to 100 MB, no SVG or AVI. On Save, `prepareBanner` (`banner-upload.ts`) re-encodes a still from the cropper's canvas (WebP, or JPEG/PNG where the browser cannot encode WebP), and sends a GIF or video through the lazily imported `banner-convert.ts` (Mediabunny over WebCodecs, its own chunk) to a muted 2.4:1 MP4. Where that returns `null`, only a GIF, MP4, M4V or WebM uploads as picked; anything else is refused. `uploadCheck` holds every uploaded file to the server's 10 MB. The targets and crop geometry live in `@repo/lib/banner`, shared with the worker's `backfill-banner-compression.ts`, so both produce the same file.

## Centrifugo

The real-time server (`centrifugo/config.json`) is reachable only on the Docker network, with `/connection` routed to it by the reverse proxy (`design/realtime-centrifugo-deploy.md`). Locally, `docker compose --env-file .env --env-file .env.local up -d centrifugo` also applies `docker-compose.override.yml`, which publishes it on `127.0.0.1:8000` for the dev server's `/connection` proxy. The `user` namespace has `presence` on, which the online dot reads. Centrifugo reads its config only on start and `up -d` leaves a running container alone, so a change to `centrifugo/config.json` needs `docker compose … restart centrifugo`, on prod before the web that relies on it.

## Error tracking

Sentry, set up in the root `AGENTS.md` (Error tracking). Every event counts against the Sentry plan's quota, which is one reason for the tunnel's per-IP limit.

- **Browser.** The DSN reaches it at runtime: the root loader's `error-tracking` query fills `<meta name="error-tracking-*">` in the shell (so it survives a failed loader). `client.tsx` reads it and only then downloads `@sentry/react`; with no DSN the browser loads none of it. It sends to `/api/errors` (`routes/api/errors.ts`), which forwards only `event` items of an envelope whose header names the configured DSN, with a per-IP limit and a size and time cap (`lib/server/error-tunnel.ts`).
- **What is reported.** Unexpected errors only. `isExpectedError` drops any oRPC error under 500 and anything with a `data.reason`, so a refusal is never reported; `orpcErrorAdapter` (`src/start.ts`) keeps both across SSR hydration. Web server: `logORPCError` (`/rpc`, `/api/v1`), the in-process SSR client in `lib/orpc.ts`, and h3's unhandled errors in `src/server.ts`. Browser: `ErrorComponent`, `WidgetBoundary` and uncaught errors, never an oRPC error, which the server reports. Worker: every `log(tag).error` (`instrument.ts` sets the sink).
- **Privacy.** Every event and breadcrumb passes `scrubEvent` / `scrubBreadcrumb` and the SDKs run with `DATA_COLLECTION` (`@repo/lib/error-scrub`): the user is its id only; no emails, wallet addresses, `/@` profile names, query strings, values quoted by a failed query, click labels, cookies, auth headers, bodies or console breadcrumbs. A new capture goes through the same init, and new private fields join its key lists: `PRIVATE_KEY` everywhere, `USER_TEXT_KEY` in `extra` and the app's own contexts (the SDK's `message`, `name` and `description` stay).
- **Source maps.** `vite build` uploads the client's maps and deletes them from `dist` only when `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT` and `SENTRY_RELEASE` are all set; `SENTRY_URL` is only for a self-hosted Sentry. CI has no token, so CI builds upload nothing.

## Verifying against production

The dev server talks to production unless `.env.local` overrides it, and the account in `SMOKE_TEST1_*` is the user's own: sign in and read, never write. A `window.fetch` shim cannot hold a write back, because `lib/orpc.ts` captures `fetch` when it builds its `RPCLink`. Verify a mutation up to the request boundary (its input and the request it would send) and leave the control unclicked.

## Pin drag-and-drop

`features/profile/pin-dnd.tsx` and `use-pin-order.ts`. The drop commits through plain React state (`pinOrderOverride`) set in the same handler as dnd-kit's cleanup, so both land in one commit; the mutation's `onSettled` clears it. React Query defers cache notifications to a later task, so `setQueryData` cannot paint in that frame, and `flushSync` commits while dnd-kit is still active. Reordering the DOM during `onDragOver` remounts `virtua` cells and kills the shift animation, hence `animateLayoutChanges: () => false`.
