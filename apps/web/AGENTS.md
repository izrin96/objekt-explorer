# web

TanStack Start app on Base UI (the cnippet registry). `src/components/ui/*` are vendored registry copies kept verbatim; `src/components/ui/README.md` lists the only local edits, and the upstream variants to check before composing a new UI pattern or a `components/shared` wrapper.

## Rules

- **State.** URL state is the route's `validateSearch` with Zod. Zustand reads are selectors (`useFilters((s) => s.member)`), never the whole store.
- **Data.** Server data goes through React Query with the `@orpc/tanstack-query` utils. Route loaders load the first paint with `queryClient.query({ ...options, staleTime: "static" })`. `useSuspenseQueries` has no `enabled: false` (it suspends forever), so fetch unconditionally and ignore the result when it does not apply.
- **Strings.** Every user-facing string is `m.*` from Paraglide. A dialog's dismiss button is `m.common_modal_cancel()` when the dialog has a primary action that commits something, and `m.common_modal_close()` when it is informational or only produces output to copy.
- **API errors.** Show an oRPC error through `refusalText(error)` (`lib/refusal.ts`) or the domain's own formatter (`features/chat/format.ts`), never `error.message`; Better Auth calls in `features/auth/` and `features/account/` keep Better Auth's message.
- **UI kit.** Phosphor icons; `virtua` for grids. An objekt grid in a dialog or sheet takes its columns from `useCardColumns` (`features/objekt/card-grid.tsx`): `VirtualCardGrid` (a `PanelCardGrid` in a `FadeScrollArea` of its own, `components/shared/fade-scroll-area.tsx`) in a fixed-height body under a filter bar that stays put, `CardGrid` for a short list inside a `SheetPanel` or `DialogPanel`, `PanelCardGrid` for a long one there (virtua's `Virtualizer` inside the panel's own scroll area, so the panel keeps its edge fades and scrollbar; Trade's "+N" sheet, `side-items-sheet.tsx`), and `CardGridSkeleton` while any loads. `PanelCardGrid` wraps its rows in Base UI's `ScrollArea.Content`: the scroll area otherwise only watches its viewport's box, and the fades miss the grid growing until the first scroll. Any other scroller of its own in a sheet, dialog or popover (a `max-h` list, a flex column) is a `FadeScrollArea`, not the vendored `ScrollArea`, whose `h-full` viewport only a set height bounds and whose focus ring the fade mask clips. The virtual grids start the next page a viewport before the end, since the sentinel's margin is measured against the window, so their `more.load` is `fetchNextPage({ cancelRefetch: false })`: the scroll handler and the sentinel can both call it before `loading` renders.
- **Components.** Before using a cnippet component, read its page as markdown: `https://ui.cnippet.dev/llms.txt` lists every page, and `.md` on a page URL gives its docs. Compose with the part names from its Anatomy section (`DialogPopup`, `MenuPopup`, `SelectPopup`) and swap the rendered element through the `render` prop (`<DialogTrigger render={<Button variant="outline" />}>`); `asChild` is Radix's API and has no effect here. Add a component as `@cnippet/<name>` (see `components/ui/README.md`): a bare name installs the shadcn (Radix) version.
- **Tokens.** cnippet token names only. `text-*-foreground` on a feedback colour is text on a tinted chip, not on a solid fill: text on a solid fill is `text-white`, and a tint is an opacity modifier on the fill (`bg-destructive/8`), since there is no `*-subtle` token.
- **Lists.** Where a list lives and who owns it key off its profile **address**; `isProfileBind` only decides whether it shows on that profile (`features/list/list-link.ts`).
- **Overflow guard.** `lib/dev-overflow-guard.ts` reports horizontal overflow in dev. Declare every deliberate horizontal scroller with `data-scroll-x`, or the guard reports it.
- **Trade page.** Its state lives in the pure `features/offers/next-step.ts` (the status card's state, its `primary` button, each side's status and each leg's chip), `exchange.ts` (a leg's status and warnings, and how The exchange groups, filters and finds legs) and `trade-clock.ts` (`timelineRows`, the one Timeline for every state), beside their tests: a new state starts there, then `next-step-banner.tsx` (the status card, which also holds the stepper) maps it to copy, worded in `next-step-text.ts` beside its test. The phone bar reads the same `primary`, so the card hides the buttons the bar carries. An open request to cancel (`trade.cancelRequest`) outranks every other running state as `theyAskCancel` (Decline and Accept, `primary: "decide"`) or `youAskCancel` (Withdraw); its dialogs live in `cancel-trade.tsx`, and the menu offers Ask to cancel only while Cancel trade is locked and no request is open.
- **Held offer actions.** Decline and Withdraw on an open offer wait `HOLD_MS` before they send. The hold lives in `stores/offer-holds.ts`, beside its timer, so it outlives the card; Undo (notice or card) calls `cancelOfferHold`, and a closed tab drops it. Pure parts are in `features/offers/hold.ts`.
- **Trade ratio.** Every surface draws a ratio with `RatioChip` (`features/list/ratio-chip.tsx`), worded in `ratio-text.ts` beside its test: `1:N` on a have side, `N:1` on a want side, "You…" for the owner and "They…" for everyone else, and for the owner a dashed chip when it follows the list's Ratio for all. The feed and the picker send only the ratio that applies; the list page and the Rules strip get each row's own and the list's, and `appliedRatio` picks.
- **Post composer.** New post and Edit post are the page `/trade/new` (`features/trade/composer/`). A caller opens it with `useOpenComposer()(start)`, which maps the `ComposerStart` to the search through `composerSearch` (`composer/link.ts`, tested; `replaces` travels as `edit`) and passes the current href as `from`, the same-origin path Post returns to. The route's loader turns the search into the start through `resolveStart`, which keeps only the viewer's own lists and posts, and the picks are page state seeded once from it. Each side's dropdown ends with a new list of its type: have and sale open `CreateListDialog` with `lockType` (type fixed, bound to a profile) and `onCreated`, which picks the list instead of offering Post it, and want opens a name-only dialog. Each picked side's thumbnails start with an Add objekts tile, opening `AddObjektsSheet` (`composer/add-objekts.tsx`) from the bottom: a bound have or sale list offers its profile's tokens, a want list every collection of the selected artists, and `add-objekts-request.ts` (tested) builds the `list.addToList` input. New lists, added objekts, rules and ratios save at once through the list page's own mutations, and only Post calls `trade.savePost`.
- **Person and post pages.** `/trade/@<handle>` and `/trade/@<handle>/<anchor slug>` (`routes/(container)/trade/@{$handle}/`). The layout's `beforeLoad` resolves the handle through `tradePersonOptions` (a one-minute stale time, so an open tab sees a changed handle), shows not found (also for a handle that can't be one), offers a retry under the plain Trade title when the lookup is refused (the rate limit), or redirects any other nickname, address or letter case to the canonical handle through `withHandle` (`features/trade/person-page.ts`), keeping the rest of the path and the search, and hands `{ userId, handle }` to the pages' loaders as context. Both pages draw `PersonPageView`, which reads the row through `peopleOptions` with `person` (`loadPersonRow` in the loader, the same key) and draws `PersonRow`; with `focus` (a post id, chosen by `slugTarget`, which also sends the other half of a pair to its anchor's slug) the row shows that post outlined, its actions address it, and "Show N more posts" adds the rest. The `head` is `sharePreview` (`share-preview.ts`, tested: handle and post contents only, never the viewer's matches) through `generateMetadata`'s `url`, which adds the description, `og:title`, `og:url` and canonical on the site's origin (`lib/site-origin.ts`, `SITE_URL` on the server). Older `person=` and `partner=` links redirect in the feed routes' `beforeLoad` (`oldPersonTarget`), before anything else; a refused lookup drops the parameter. Copy link always builds a page URL through `useCopyTradeLink({ handle, slug? })` and is a `CopyLinkItem` in a ⋯ menu, disabled with its reason when there is no handle.
- **Feature order.** `features/` imports run one way: list < offers < chat < trade, so a feature imports only the ones below it; a symbol two features share goes down to `lib/`, `components/shared/` or the lower feature. The exceptions: list's page shell (`list-view`, `list-header`, `edit-list-dialog`, `create-list-dialog`) imports trade and chat for Post it and `MessageButton`, and offers imports chat's `queries.ts` and `format.ts`, since an offer is a chat message.
- **Section chrome.** A route under `trade/` that brings its own heading sets `staticData: { tradeChrome: false }` (declared in `router.tsx`), and `trade/route.tsx` then drops the Trade header and tabs; the trade page uses it for its breadcrumb.

## Look

Quiet chrome, loud cards. The page is neutral zinc in both themes, with a near-black or white primary, and the objekt cards carry the colour. Colour elsewhere means something and comes from `lib/tone.ts`: list types (have teal, want amber, sale rose), progress indigo, and success, warning and destructive, each a chip of ink on a tint with an edge in Badge's recipe. Indigo `accent` is for focus and the current selection, not decoration. `font-mono` (JetBrains Mono, slashed zero) marks an identifier, a value read character by character to copy or compare: serials, collection numbers, addresses, deal numbers. Every other number (counts, prices, percentages, ranks, dates) is the sans with `tabular-nums`; labels, badges and names are the sans; prose is the sans (Google Sans Flex) and titles are `font-display` (Instrument Sans). Metadata reads as a " · " line. A new screen reuses these tokens and the vendored components before it adds anything; a design skill's palette, font or motion library gives way to this.

## Chat deals

`features/chat/deal-text.ts` is the one place a deal state is worded and toned, for the Inbox row and the thread's deal strip alike, beside its test against the spec's tables. Below `md` the strip drops "v of t" and reads `phoneWords` where set (the row's shorter words for Your turn, Their turn and Stuck), so whose turn it is fits a phone. A trade step's chip words come from `stepChipText` (`features/offers/next-step-text.ts`), which the status card shares. It stays free of network imports, so the strip passes `leftLabel` and `shortDate` in. The trade page's step tones live in `STEP_TONE` (`lib/tone.ts`), which the status card and the deal read. A message that may not be loaded yet is reached through `useJumpToMessage` (`thread/thread-hooks.ts`), which loads up to 10 older pages, keeps the reader's place and focuses the target, and with `highlight` tints it through its `data-highlight` styles; Review offer, View offer, the New divider and a reply's quote use it. The Inbox's `show` chip keeps the open conversation's row after it stops matching (`kept-row.ts`), until a chip is picked or the search changes.

## Offer builder

Make offer and Counter are the page `/trade/@<handle>/offer` (`routes/(container)/trade/@{$handle}/offer.tsx`), never a dialog. Every caller links through `offerLink` (`features/offers/offer-link.ts`, tested): `MakeOfferButton` as a link, `useOpenOffer()` from a menu item or a drawer, both passing the current href as `from`. The search says how the offer starts (a list or conversation, the row's or one post's matches, a near pick, `counter`, a Market listing's `ask`), never the sender's picks; `requestOf` rebuilds the `OfferRequest` from it, and the loader reads a counter's offer (`offer.views`, refused unless `actions` has `counter`) checks that a conversation is the viewer's with this person, and starts from the person (`withoutLists`) when a list the search names isn't theirs. `partnerHandle` gives chat and the trade page a handle: a post card's, else the address, since a nickname can be shared.

`OfferPage` (`offer-builder.tsx`) lays the page out through `builder/layout.tsx`: `BuilderGrid`, the title in `BuilderTitle`, and `BuilderBody`'s slots (`sides`, `details`, `hint`, `cancel`, `send`, `picker`), from `lg` the title over a sticky column beside the sides (the title scrolls away, so the DOM reads title, status line, sides, details at every width), and below `lg` one column with a bottom bar. A request with `matches` opens through `MatchesBuilder`: it draws the title and one region for the matches line (`role="status"`, `STATUS_AREA`, above the sides; each side keeps its own banner for blocked picks) that stays mounted from the first frame to the leaving, reading "Adding your matches…", then the line or the failure; the body beside it changes from placeholders to `BuilderForm`, which portals its line (`builder/matches-line.tsx`, with Remove matches and Undo) into that region, so a screen reader hears every change in one node. A request without `matches` has no region. `BuilderForm` and `BuilderRefused` never draw the title: their caller does. The picker (`offer-picker.tsx`) is a sheet as wide as the main area.

Leaving goes through `useBlocker` on `holdsDraft` (`builder/draft.ts`), with the browser's prompt on a reload; a sent offer skips it and replaces the page with the conversation. Back and Cancel (`useLeaveOffer`) step back through history when the page was opened in the app (`offerBack` in the history state, which the handle redirect keeps), so a feed comes back scrolled, else replace it with `from` or the person page. The control that opened the page takes focus again through the one-shot opener in `features/offers/return-focus.ts`: a Make offer link by its start, chat's Add to message as `chat-add:<id>`; a sent offer forgets it. Make offer links never preload, since each preload spends the feed's rate limit.

## Chat draft

`stores/chat-draft.ts` keeps, per conversation id and in memory only, the card a Message button hands over and the unsent `body` with the `clientId` of the send being composed. The composer reads it through selectors. A failed send restores its text in the send mutation's `onError`, not the per-call one, because that one is lost when the thread unmounts. The same `clientId` goes with every retry so the server posts the message once; editing the text starts a new one, and so does choosing, changing or stopping a reply.

The draft also carries the reply, with a snapshot of its quote, and keeps it while the box is empty. A send in flight leaves its reply in `sentReplies`, as its card waits in `sentCards`, so a failure puts both back; a reply started or a card attached meanwhile wins (the open thread lists its card in `boxCards`), and the failed text returns without its own. The reply line reads the cached message first (`features/chat/reply.ts`), and `applyUnsent` blanks a snapshot whose message was unsent.

The card is an `Attachment` (`features/chat/attachment.ts`) of two kinds: an objekt card (`kind: "objekt"`, drawn as a chip) and a Trade post card (`kind: "post"`, drawn by `thread/post-card-message.tsx`, the component the thread uses). Only a Trade row's Message (Browse, For you and the person pages, one row per person, addressed to the row's lead post, or on a post page to that post) attaches a post card; its `withMatch` asks the server for the match, and the first-line suggestion follows `view.match`, the match the server saved.

## Presence

A person's online dot is `OnlineAvatar` (`features/presence/online-avatar.tsx`), a green dot while online and an amber crescent (`TONE_SOLID.warning`) while idle, and text that says "Online" or "Idle" reads `usePresenceStatus(userId)` (`"online" | "idle" | null`, `null` before hydration); `PersonAvatar` stays free of presence, since the hover card, Market and signed-out pages use it. Pass no `userId` for the viewer's own avatar. `usePresenceStatus` watches the id while it is mounted, so the watched set is what is mounted (all of a plain list, only the rows on screen of a virtua one), an id no avatar shows any more forgets its answer, and the tab's one `usePresencePoller`, mounted beside `useUserSocket` for signed-in users only, asks `presence.online` for it (`stores/presence.ts`, pure parts in `watch.ts`, where `applyPresence` keeps `idle` a subset of `online`), reading `idle ?? []` for a server from before it. A failed or refused check changes nothing. Beside the poller, `useActivityReporter` tells the server the viewer is active: on a pointer press or move, a key or the wheel in a visible tab, on coming back to the tab and once on mount, it sends `presence.active` when `shouldReport` (`activity.ts`) allows, at most once a minute. It does not listen for `scroll`, which also fires for scrolls the app makes. A failure shows nothing and lets activity retry after 10 s (`failedReportAt`).

## Banner upload

The Edit profile dialog never uploads a banner as picked unless it must. `bannerPlan` (`features/link/banner-rules.ts`, tested) decides at pick time: stills up to 25 MB, GIF and video up to 100 MB, no SVG or AVI. On Save, `prepareBanner` (`banner-upload.ts`) re-encodes a still from the cropper's canvas (WebP, or JPEG/PNG where the browser cannot encode WebP), and sends a GIF or video through the lazily imported `banner-convert.ts` (Mediabunny over WebCodecs, its own chunk) to a muted 2.4:1 MP4. Where that returns `null`, only a GIF, MP4, M4V or WebM uploads as picked; anything else is refused. `uploadCheck` holds every uploaded file to the server's 10 MB. The targets and crop geometry live in `@repo/lib/banner`, shared with the worker's `backfill-banner-compression.ts`, so both produce the same file.

## Verifying against production

The dev server talks to production unless `.env.local` overrides it, and the account in `SMOKE_TEST1_*` is the user's own: sign in and read, never write. A `window.fetch` shim cannot hold a write back, because `lib/orpc.ts` captures `fetch` when it builds its `RPCLink`. Verify a mutation up to the request boundary (its input and the request it would send) and leave the control unclicked.

## Pin drag-and-drop

`features/profile/pin-dnd.tsx` and `use-pin-order.ts`. The drop commits through plain React state (`pinOrderOverride`) set in the same handler as dnd-kit's cleanup, so both land in one commit; the mutation's `onSettled` clears it. React Query defers cache notifications to a later task, so `setQueryData` cannot paint in that frame, and `flushSync` commits while dnd-kit is still active. Reordering the DOM during `onDragOver` remounts `virtua` cells and kills the shift animation, hence `animateLayoutChanges: () => false`.
