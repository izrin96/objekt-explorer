# Trade

Part of `apps/web/AGENTS.md`, which points here.

## Trade ratio

Every surface draws a ratio with `RatioChip` (`features/list/ratio-chip.tsx`), worded in `ratio-text.ts` beside its test: `1:N` on a have side, `N:1` on a want side, "You…" for the owner and "They…" for everyone else, and for the owner a dashed chip when it follows the list's Ratio for all. The feed and the picker send only the ratio that applies; the list page and the Rules strip get each row's own and the list's, and `appliedRatio` picks. On the Trade strip, Trade's "+N" sheet and the composer, the chip lies inert over the card's bottom-end corner (`RATIO_ON_CARD`, the pair of the copy count's `QTY_BADGE`, both in `objekt-card.tsx`), so the tile, card or trigger carries its `ratioName` as the tooltip; the list page and the offer builder keep it under the label.

## Post composer

New post and Edit post are the page `/trade/new` (`features/trade/composer/`). A caller opens it with `useOpenComposer()(start)`, which maps the `ComposerStart` to the search through `composerSearch` (`composer/link.ts`, tested; `replaces` travels as `edit`) and passes the current href as `from`, the same-origin path Post returns to. The route's loader turns the search into the start through `resolveStart`, which keeps only the viewer's own lists and posts, and the picks are page state seeded once from it. Each side's dropdown ends with New … list… and then Copy a list…. New opens `CreateListDialog` with `lockType` (type fixed; have and sale bound to a profile with no None, want unbound with the profile optional) and `onCreated`, which picks the list instead of offering Post it. Copy, shown while the viewer owns a list, opens `ComposerCopyDialog` (`composer/copy-list-dialog.tsx`): Copy from takes any of the viewer's lists, and `CopyListForm` copies it with the side's type fixed and picks it the same way. `ListSelect` ignores a value change whose reason is `"none"` unless a key on its trigger caused it: Base UI clears a value its items don't hold yet, which a just-made list is until the refetched lists render, and reports that reset with the same reason as closed-trigger typing. Typing never lands on New or Copy, so a letter never opens a dialog. The pick runs in `mutate`'s per-call `onSuccess`, so a dialog closed while the request is in flight picks nothing. Each picked side's thumbnails start with an Add objekts tile, opening `AddObjektsSheet` (`composer/add-objekts.tsx`) from the bottom: a bound have or sale list offers its profile's tokens, a want list every collection of the selected artists, and `add-objekts-request.ts` (tested) builds the `list.addToList` input. A pencil beside each picked side's name opens `EditListDialog` with `showTradeLine={false}`, since its Edit post or Post it would reopen this page and drop the picks; that also hides a want list's Open to, which Post sets, as `lockType` hides it in New and `fixedType` in Copy. Each thumbnail in the preview is a menu of the list page's Set price, Set ratio and Remove dialogs, mounted once per side by `useSideDialogs` (`composer/use-side-dialogs.tsx`) and opened through its `actions`. "+N" and a side's Select open `AllObjektsSheet` (`composer/all-objekts.tsx`) from the bottom, in the Add objekts sheet's shape: a tap ticks a card and no card has a menu; the ticks are local state of entry ids, never the shared selection store, and the ticked objekts are derived from the entries, so one that leaves the list leaves the ticks; `PickerFilterBar` filters the loaded entries in the browser, and ticks the filter hides stay in the tray and in the count on Remove; the actions call `bulkActions`, passing the control focus returns to (the Change menu passes its trigger, since the item is gone by then); on a sale side each price and note sit under the card, outside the tile's control. Its Add objekts swaps the sheet's content in place and sets `focusTitle`, since no popup opens to move focus. Both sheets share `TickedTray`, `TickTile` and `tickedName` (`composer/ticked-tray.tsx`, `tick-tile.tsx`, `ticked-name.ts`). A remove can remount the preview's thumbnails (the objekt sliding in from behind "+N"), so `finalFocus` is a function that looks the target up by entry id as the dialog closes: the objekt's own thumbnail, or after a remove (`onRemoved`) the next one, else whatever took the removed one's place, else the Add objekts tile. In the sheet a dialog returns focus to the control that opened it, or after a remove to the sheet's title, since every action is then disabled. A remove there can also take "+N" or Select off the page, so the sheet's own `finalFocus` falls back to the side's Add objekts tile (`data-add-tile`). New lists, list edits, added and removed objekts, prices, rules and ratios save at once through the list page's own mutations, and only Post calls `trade.savePost`. Leaving goes through `useBlocker` on `picksChanged` (`composer/link.ts`, tested), with `done` set before Post, Save or Take off Trade navigates; Cancel and those return through `returnAfter`, which moves a return to the edited post's own page to its new anchor, or Browse once it is off Trade. Under a have or sale side, `trade.unshownEntries` names the entries Trade leaves out (not owned or not transferable); it sits under `trade.key()`, so every list write refetches it. The trade-block warning reads `tradeBlocked` from `trade.myPosts`, so a first post under a block goes unwarned.

## Person and post pages

`/trade/@<handle>` and `/trade/@<handle>/<anchor slug>` (`routes/(container)/trade/@{$handle}/`). The layout's `beforeLoad` resolves the handle through `tradePersonOptions` (a one-minute stale time, so an open tab sees a changed handle), shows not found (also for a handle that can't be one), offers a retry under the plain Trade title when the lookup is refused (the rate limit), or redirects any other nickname, address or letter case to the canonical handle through `withHandle` (`features/trade/person-page.ts`), keeping the rest of the path and the search, and hands `{ userId, handle }` to the pages' loaders as context. Both pages draw `PersonPageView`, which reads the row through `peopleOptions` with `person` (`loadPersonRow` in the loader, the same key) and draws `PersonRow`; with `focus` (a post id, chosen by `slugTarget`, which also sends the other half of a pair to its anchor's slug) the row shows that post outlined, its actions address it, and "Show N more posts" adds the rest. The `head` is `sharePreview` (`share-preview.ts`, tested: handle and post contents only, never the viewer's matches) through `generateMetadata`'s `url`, which adds the description, `og:title`, `og:url` and canonical on the site's origin (`lib/site-origin.ts`, `SITE_URL` on the server). Older `person=` and `partner=` links redirect in the feed routes' `beforeLoad` (`oldPersonTarget`), before anything else; a refused lookup drops the parameter. Copy link always builds a page URL through `useCopyTradeLink({ handle, slug? })` and is a `CopyLinkItem` in a ⋯ menu, disabled with its reason when there is no handle. The links in are a row menu's View Trade page (left out on the person page itself), a post menu's and a Your posts entry's View post (left out on that post's page), and the list page's On Trade badge through `tradePostLink` (`features/list/list-link.ts`, tested: the list's profile address, else its linked list's, the layout redirecting the address to the handle and `$slug.tsx` a want half to its anchor slug; `/trade` with neither). Each is a `ReasonItem` (`copy-link-item.tsx`) or a link with `preload={false}`, since a page's loader reads the row against the feed's rate limit. The owner is `userId === user.id`, not the row: with no row the owner gets `ownEmptyKind` (`my-posts-summary.ts`, tested) over `trade.myPosts` (no posts, trade block, all idle, nothing left to show), and while that loads the generic empty state. Bump stays per person (Your posts, the own person page's row, the post page), never in a post's menu, which carries the owner's Edit post and Take off Trade (`OwnPostItems` in `post-block.tsx`, mounted only for the owner's posts). On a post page the row's Report… names the focused post (`post` on `SafetyMenu`); elsewhere it names none. Each other person's post's ⋯ menu ends with Report this post… for a signed-in viewer, whose `PostReport` child mounts on the click only (it holds the report and block hooks) and returns focus to the ⋯ button through `finalFocus`.
